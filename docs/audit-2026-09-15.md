**Scope:** `app/`, `firebase/functions/`, `shared/`, `firebase/*.rules`, `scripts/`, repo root

> **▲ IMMEDIATE ACTION REQUIRED**
> This is a well-architected, security-conscious codebase — but it ships with **zero automated tests, zero CI, and no branch protection** guarding prize-award, billing-plan, and multi-tenant-isolation logic, which is the single largest risk to the project. Two concrete security gaps deserve attention before the next event: **(1)** Firestore rules made *every* campaign — including unpublished **draft** hunts, their prizes, and unreleased target photos — world-listable via the public Firebase project config (`firestore.rules`), and **(2)** the unauthenticated `verify-capture` endpoint drives paid Gemini spend behind a rate limiter that **fails open** (`rateLimit.ts`), so an IP-rotating client can uncap platform cost. Neither is an active data-breach of PII (the app deliberately stores almost none), and no secrets are committed anywhere in the working tree or the full 40-commit history. The urgent work is process maturity (tests + CI gate) and a rules/headers hardening pass, not firefighting.

## 2. Technical Audit

### 2.1 Security Findings

#### S-1: Draft (unpublished) campaigns were world-readable and world-listable via Firestore rules — **FIXED**
* **Severity:** Medium (High for embargoed hunt content) | **CWE:** CWE-639 / CWE-284 | **OWASP:** A01:2021 Broken Access Control
* **Design Flaw:** `firestore.rules` granted `allow read: if true` on `tenants/{slug}/campaigns/{campaignId}`. In rules v2 `read` covers both `get` and `list`. The API only ever *serves* the single **published** hunt (`campaigns.ts` `getPublishedMissionList`), but the rule did not encode that restriction, and the public Firebase web config makes the Firestore surface reachable by anyone.
* **Exploitation:** init the JS SDK with the public project id → guess an org slug (public, on QR codes) → `getDocs(collection(db,'tenants',slug,'campaigns'))` returns **all** campaigns, `status:'draft'` included, with `name`, `prize`, `winnerLimit`, and every `targetImageUrl`.
* **Evidence:** `firebase/firestore.rules` (campaign match); `firebase/functions/src/helpers/campaigns.ts:136`.
* **Remediation applied:** split `get` (published-or-member/operator) from `list` (member/operator only). The app never reads Firestore directly (verified: no `getFirestore`/`firebase/firestore` import in `app/src`), so this cannot break the client. Add a rules unit test as follow-up.

#### S-2: Unauthenticated `verify-capture` → paid model spend behind a fail-open limiter — OPEN
* **Severity:** Medium | **CWE:** CWE-770 + CWE-703 | **OWASP:** API4:2023 Unrestricted Resource Consumption
* **Design Flaw:** `POST /t/:slug/verify-capture` is intentionally anonymous (`api.ts`) and each call forwards a ~1 MB image to Gemini. The per-IP (30/60s) and per-tenant (50,000/day) guards **fail open** by design (`rateLimit.ts:93`), so the platform cost ceiling is bypassable under the load an attacker induces.
* **Why not auto-fixed:** the fix (a **fail-closed** global daily circuit breaker) contradicts the codebase's explicit "a fan must never lose a capture to our bookkeeping" philosophy — flipping to fail-closed could block every capture platform-wide during a Firestore blip at a live event. This is a product/design tradeoff, not a mechanical fix.
* **Remediation:** add a fail-closed *global* daily model-call breaker (bounds worst-case spend while keeping the per-fan verdict lenient); set a GCP billing budget alert + Generative Language API quota cap as the backstop; consider requiring Firebase anonymous auth on the endpoint.

#### S-3: No HTTP security headers / CSP on hosting; SVG uploads permitted — OPEN (hosting config)
* **Severity:** Medium | **CWE:** CWE-693 / CWE-79 (latent) | **OWASP:** A05:2021
* `firebase.json` `hosting.headers` sets only `Cache-Control` — no CSP, `X-Content-Type-Options`, `frame-ancestors`, `Referrer-Policy`, or HSTS. `storage.rules` accepts any `image/.*` including SVG (comment acknowledges SVGs can embed script; currently mitigated by `<img>`-only rendering from a separate origin).
* **Remediation:** add strict CSP + `nosniff` + `frame-ancestors 'none'` + `Referrer-Policy` + HSTS to `firebase.json`; either block `image/svg+xml` at the storage rule or document+enforce `<img>`-only rendering. Deferred here because CSP needs to be validated against the running app before shipping.

#### S-4: Forgeable claim code / self-reported fan progress (documented open seam) — OPEN (by design)
* **Severity:** Medium | **CWE:** CWE-602 | **OWASP:** A04:2021 Insecure Design
* `PUT /me/progress` stores whatever the authenticated client claims (`fanProgress.ts`); badge/claim codes are client-derived. Safe only because product policy is "no prize without staff verification." Before any self-serve redemption ships, make badges server-authoritative and mint/invalidate claim codes server-side. **Do not build speculatively** (per CLAUDE.md) — it carries its own PII/fraud decisions.

#### S-5: Hardcoded CORS allow-list pinned to the pre-rename project origin — OPEN
* **Severity:** Low | **CWE:** CWE-1188 | **OWASP:** A05
* `cors.ts` hardcodes `stadium-photo-hunt.web.app`/`.firebaseapp.com` while the product is renamed to **Huntima** (project id pending). On rename, deployed CORS breaks or drifts. Drive `ALLOWED_ORIGINS` from env/secret per environment; add the production origin at rename time.

#### S-6: `POST /echo` reference endpoint exposed in production — **FIXED**
* **Severity:** Informational | **CWE:** CWE-489 (Active Debug Code)
* `api.ts` reflected arbitrary parsed JSON on a deployed function. **Remediation applied:** gated on `isEmulator` (returns 404 in production), matching the seed-admin route.

**Positives verified (not findings):** admin authority is a *verified custom claim*, never an email/domain (`auth.ts`); org access is a membership document with instant revoke; plan changes are operator-only; branding entitlement enforced server-side (`tenant.ts`); last-owner invariant transactional (`members.ts`); publish-exclusivity transactional (`campaigns.ts`); slug regex is **not** ReDoS-vulnerable; seed-admin double-gated on `isEmulator`; fan capture images never persisted.

### E. Glossary
* **IDOR** — accessing another party's object by manipulating an identifier.
* **Fail-open / fail-closed** — on internal error, *allow* vs *deny* the request.
* **CSP** — Content-Security-Policy; browser header restricting resource/script origins.
* **ReDoS** — regex denial of service via catastrophic backtracking.
* **Custom claim** — signed, server-set field in a Firebase Auth token (`admin` = platform operator here).
* **Membership document** — `tenants/{slug}/members/{uid}`; the authoritative org-access grant.
* **Seam** — a deliberately-deferred extension point (per `docs/architecture.md`), not an oversight.
* **N+1** — one query per item instead of a single batched query.
* **SAST / SCA** — Static Application Security Testing / Software Composition Analysis.
